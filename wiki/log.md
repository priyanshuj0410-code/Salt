## [2026-05-30] fix | Harden order saves (timeout + no duplicate submit)
Live verification showed `place_order` (sale) persists correctly — order, walk-in link, cash=paid, and stock decrement all confirmed against the real DB — but the client could hang on "Saving…" when the RPC response didn't return (a CDP/automation artifact here, but a real risk on flaky networks), which invited a duplicate by retrying. Added `withTimeout` + `TimeoutError` to `lib/orders.ts`; `BillSummary.save` and `PurchaseEntryPage.save` now race `place_order` against a 15s timeout, guard re-entry (blocks F9 while saving), and on timeout show a cautionary "may have gone through — check before saving again" message instead of stranding. → [domain/orders](domain/orders.md)

## [2026-05-30] fix | Page past PostgREST's 1000-row cap on reads
The stock step matched only ~995 of 7,871 items: `EntityStep.buildCtx` read items via `.select()`, which PostgREST caps at 1000 rows, so `itemByCode` was truncated and most stock rows quarantined as "not in catalogue". Added `lib/selectAll.ts` (range-based pagination) and applied it to every large-list read: `buildCtx` (item join), `catalog.ts` (billing catalogue — would otherwise show only 1000 items), `PartyGstStep` (ledger match), `PartiesPage` (parties + bills). Orders lists are still single-page (low volume on a fresh shop) — revisit when they can exceed 1000. → [architecture/import-pipeline](architecture/import-pipeline.md)

## [2026-05-30] fix | items upsert needs a non-partial unique index
The items step upserts on `ON CONFLICT (org_id, item_code)`, but 0012 created that uniqueness as a **partial** index (`WHERE item_code IS NOT NULL`) — Postgres can't use a partial index as an ON CONFLICT target unless the statement repeats the predicate (which PostgREST can't), so the import errored "no unique or exclusion constraint matching the ON CONFLICT specification." Changed `items_org_code_idx` to non-partial (NULL codes still allowed — NULLs are distinct in a unique index). Live DBs need: `drop index if exists public.items_org_code_idx; create unique index items_org_code_idx on public.items (org_id, item_code);`

## [2026-05-30] fix | Auto-pick the org's working shop (self-healing primary)
`useAuth` resolved the shop via `is_primary = true`, so orgs whose imports created shops without flagging one — i.e. every shop in the live data — were stuck with `shop = null` and the rescue dialog was useless. Now picks the shop with the best `(is_primary desc, created_at asc)` (primary wins; else the oldest) and self-heals by promoting that pick to primary so the next load is deterministic. Errors on the promote are swallowed (a unique-per-org race resolves on `refresh()`).

## [2026-05-30] fix | Allow negative stock on import (it's real)
The batches validator quarantined `qty < 0` as an error, but negative on-hand stock is a genuine real-world value (oversold, or billed before the GRN landed) — blocking it isn't faithful.
